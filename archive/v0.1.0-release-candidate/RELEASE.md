# Reproducible archive-release procedure

**State on 2026-10-17:** release candidate; no public repository, GitHub Release, Zenodo deposit, DOI, external referee decision or deployed Koios coverage established.

1. **Source freeze.** Use the four existing canonical Science manuscript blob IDs linked in README, the single historical birth carrier, the fixed versioned edition and its exact SHA-256 records. Verify complete local file bytes; metadata alone is not proof. The prepared PDF currently contains 72 pages, and the infographic belongs to the release bundle.
2. **Public repository creation.** Coesite's authorized repository-formation owner must create the already named public `lenticule-science/white-repopulation`, seed the release ZIP, retain license and both credit/disclosure paths, and enable an actual public landing page. The connected GitHub operator cannot create an organization repository; see operations-services-section#27. Never silently repurpose a different owned repo as the supposed public paper.
3. **Reproducible build.** Bind the current Research Paper Authoring structural checks, the existing Pandoc document-projection service and a source-pinned toolchain. Record build tool versions, paper source/ref, figure/data inputs, exact PDF output digest, build invocation and actual test result. The current polished layout is a checked reading edition; it is **not** yet a deterministic CI-produced PDF from an independently verifiable exact manuscript build.
4. **Tagged immutable artifact.** Publish a genuine GitHub `v0.1.0` release **after** source, license and permissions are qualified. Verify the served public ZIP/PDF/CSV bytes and exact source ref; update `publication.json` to `published` only when that receipt exists.
5. **Archive and DOI.** Enable and verify Zenodo on the actual public GitHub repository, then archive the specific GitHub tag. Keep `CITATION.cff` and `.zenodo.json` consistent; Zenodo may prioritize its own manifest. Set `doi` only after repository metadata and DOI resolution can be independently read. Do not assign a fictional identifier.
6. **Communicate to Koios.** After public receipt, project a versioned source event into the source-broker/house-feeds circuit. Treat a change to a paper version or scholarly status as a corrected source; keep new article selection under newsroom evidence, desk and independent-editor permissions. Verify actual served article and correction route before claiming automatic coverage.

The release manifest carries **claimed** artifact bytes and checksums; an evaluator or CI must independently recompute and compare those bytes rather than trusting the claims. Red Cup owns execution code; Coesite owns research/release operating parameters; Causeway owns instance editorial choices.
